# Architecture

Status: verified release architecture.

## Runtime Shape

The intended production shape is one Node 24 process serving:

- built Vite client from `dist/client`;
- REST API under `/api`;
- Socket.IO under `/socket.io`;
- persistent game/session state under `DATABASE_PATH`.

The production build emits `dist/server/index.js`; `npm start` serves the API, Socket.IO, and `dist/client` from one Node process.

## Data Flow

1. `vendor/mofa-dengxiantai/cards/*.csv` and `vendor/mofa-dengxiantai/UPSTREAM_COMMIT` are the vendored upstream source.
2. `npm run sync:upstream` validates row counts and writes `src/shared/data/upstream.generated.ts`.
3. `src/shared/data/content.ts` maps generated rows into typed characters, opportunities, calamities, and fates.
4. `createGame(config)` creates a `GameState` with `schemaVersion: 2`, `rulesVersion: upstream-v0.1`, and the upstream SHA.
5. `getLegalActions(state, seatId)` returns fully instantiated legal action IDs.
6. `applyAction(state, action)` rejects stale/fabricated action IDs and appends public events.
7. `getViewForSeat(state, seatId)` hides other seats' hands, fates, unrevealed plans, and unrevealed votes.
8. `chooseHeuristicAction(state, view, seatId)` chooses one legal action for local bots, simulations, and server-side timeout fallback.
9. Active online rooms persist `actionDeadlineAt` with the authoritative revision. A server sweep applies one safe legal action for each timed-out human decision, records it in the action ledger and SQLite event stream, advances bots, and broadcasts a new seat-redacted snapshot.

## Server Contract

The client currently expects:

| Method/path | Purpose |
|---|---|
| `GET /api/health` | Health check |
| `GET /api/providers` | Provider diagnostics |
| `POST /api/rooms` | Create lobby room |
| `POST /api/rooms/join` | Join an online room by room id or code |
| `POST /api/rooms/ready` | Mark a human seat ready |
| `POST /api/rooms/start` | Host starts the game |
| `POST /api/rooms/command` | Submit a seat action with `commandId`, `seatToken`, and `baseRevision` |
| `GET /api/saves` | Host-authenticated, room-scoped save metadata |
| `POST /api/saves` | Host-authenticated online checkpoint |
| `PUT /api/saves/:id` | Overwrite a checkpoint in the same room |
| `DELETE /api/saves/:id` | Delete a checkpoint in the same room |
| Socket.IO `room:*` | Create/join/reconnect/ready/start/command/seat-order/host/bot lifecycle acknowledgements |
| Socket.IO `chat:send` / `chat:message` | Send and broadcast public chat |

## Invariants

- The shared engine must stay deterministic for a fixed seed and action sequence.
- AI and human seats must submit only action IDs from the legal action enum.
- Browser clients must never receive API keys, provider base URLs supplied by other clients, other players' private cards, fates, unrevealed plans, or unrevealed votes.
- Commands must be idempotent by `commandId` once the server exists.
- A persisted action deadline is revision-bound; chat, reconnect, and snapshot reads must not reset it.
- Persisted state must record schema version and upstream commit.
