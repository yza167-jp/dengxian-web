## 产品目标

把实体桌游《末法登仙台》做成可发布的中文网页游戏。产品必须在没有任何外部 API Key 时可完整游玩，也可使用 DeepSeek 驱动 AI；同一套确定性规则引擎同时服务单人、在线混合房间、自动模拟、存档恢复和回放校验。

## 用户模式

### 单人

- 一名真人加 3–5 名 AI，默认四人快速开局。
- 可配置 4–6 人、人物、AI provider、模型、难度、persona 和 seed。
- 自动保存、命名存档、导入导出、退出后继续。
- `local-bot` 永远可用，外部 provider 失败后自动降级。

### 在线房间

- 2–6 名真人与 AI 混合入座，无账号，房间码 + 安全座位令牌。
- 房主可换座、增删 AI、开始、转移房主和授权 Bot 临时接管断线席位。
- Socket.IO 实时同步；刷新或短暂断线凭令牌回座。
- 在线动作显示服务端倒计时；到期后按当时合法动作执行安全默认选择并写入事件日志，避免房间永久卡死。
- 服务端持有唯一真实状态；房间与对局在进程重启后恢复。
- 每个连接只获得其座位有权看到的脱敏视图。

### 规则与教学

- 首次进入提供交互式教学；游戏内可随时查看完整规则、阶段、词条和合法动作原因。
- 忠实规则模式默认且不可静默改写。
- 便利或实验平衡仅能作为默认关闭、清楚标注的预设。

## 功能范围

- 实现 4–6 人、最多 8 轮、三阶段天劫、秘密四选一与投入、机缘/神通/反应窗口、探索/修炼/修台/抗劫、贡献排序、雷击/裂痕、秘密投票、强行破界、天命与席位排名。
- 实现全部 7 名人物、48 张机缘、18 张天劫和 12 张秘密天命。
- 每轮天劫揭示后提供公开谈判聊天与快捷承诺；AI 每轮至少公开发言一次。
- 主菜单、单人配置、在线大厅、游戏桌面、规则教学、设置诊断、存档管理和结算全部可达且有错误恢复路径。

## 架构契约

- `src/shared/game` 是纯 TypeScript 确定性引擎，导出 `createGame`、`getLegalActions`、`applyAction`、`getViewForSeat`、`checkOutcome`。
- 服务端验证 `seatToken`、`commandId`、`baseRevision`、当前阶段和合法动作 ID 后才迁移状态。
- SQLite 保存房间、座位、对局快照、事件、命令幂等键和存档；记录 `schemaVersion` 与上游 SHA。
- 随机性仅来自可注入 seeded RNG；事件序列可重建并校验状态摘要。
- Zod 校验 HTTP、WebSocket、存档和 AI 输出。
- 生产构建由一个 Node 24 进程同时托管前端、HTTP 与 WebSocket；Docker 使用持久卷。

## AI 契约

- AI 只从服务端已完全实例化的合法动作 `enum` 中选择。
- DeepSeek 默认 `https://api.deepseek.com`、`deepseek-v4-flash`；高质量为 `deepseek-v4-pro`。
- 优先强制 `choose_action` tool call；严格 schema 使用 DeepSeek beta base URL；不支持时退回 JSON Output。
- 对可重试错误做有抖动指数退避，总等待有硬上限；仍失败立即用启发式 Bot。
- 浏览器永远不读取 Key 或任意 provider base URL；日志不保存原始 `reasoning_content`、完整 prompt 或其他玩家私密状态。

## 隐私与安全不变量

- 他人的手牌、天命、未揭晓计划、投入和投票从不出现在当前客户端快照中。
- 房间码与座位令牌不可预测；令牌只以哈希形式持久化。
- 聊天限长、限频并按纯文本渲染。
- 命令按 `commandId` 幂等；重连不得重复结算。
- 导入存档需要版本、结构、规则 SHA 与状态不变量校验。
- 客户端不能指定文件路径、外部 URL、API Key 或服务器环境变量。

## 视觉与无障碍

- 方向为“末法玄坛”：玄黑石台、旧金线框、雷紫、朱砂和玉青；实际使用上游四张展示图。
- 桌面优先，并验证 1024×768、1280×720、1440×900、1920×1080。
- 卡牌可放大，合法目标有文字和颜色双重标识；阶段、锁定、揭晓、雷击、裂痕与飞升有克制反馈。
- 支持键盘焦点、色弱可辨标志、足够对比度、总静音、音量和 `prefers-reduced-motion`。
